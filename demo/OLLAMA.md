# Local Ollama integration (T5)

The T5 user reported team agreement on 2026-11-22 to use local Ollama with
`qwen3:4b-instruct`. The confirmation was supplied in the working conversation;
no separate GitHub approval link was supplied. This is not a human answer-grade
record. The earlier `qwen3:4b` tag entered thinking and exhausted short token
budgets, so it is not the model used by this recipe.

## Environment and connection

Run from the repository root. Install Ollama separately, keep the local server
running, and download `ollama pull qwen3:4b-instruct`. The tested local endpoint
is `http://localhost:11434/v1`; do not substitute the Ollama cloud endpoint.

The Conda-based Python 3.12 environment crashed while importing ONNX Runtime.
An independent Python 3.11 environment is used for this integration. One way
to create it without replacing the system Python is:

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install uv
$env:UV_PYTHON_INSTALL_DIR = Join-Path (Get-Location) '.tmp/python'
$env:UV_CACHE_DIR = Join-Path (Get-Location) '.tmp/uv-cache'
./.venv/Scripts/uv.exe venv --python 3.11 --managed-python .tmp/ollama-venv
./.venv/Scripts/uv.exe pip install --python .tmp/ollama-venv/Scripts/python.exe -r requirements-dev.txt
```

The `.venv` command is for a fresh setup; reuse an existing suitable environment
rather than replacing one. On the affected machine, run these process-only
settings before the commands below:

```powershell
$env:PATH = (($env:PATH -split ';') | Where-Object { $_ -notlike '*anaconda3*' }) -join ';'
$env:OPENAI_BASE_URL = 'http://localhost:11434/v1'
$env:OPENAI_API_KEY = 'ollama'
$env:LLM_MODEL = 'qwen3:4b-instruct'
$env:NO_PROXY = 'localhost,127.0.0.1,::1'
```

`ollama` is a dummy SDK key for the local server, not a secret or a cloud key.
These explicit process values take priority over the repository's optional
`.env` file. Keep `embedding.provider=local` in `demo/ollama.toml`.
`NO_PROXY` keeps the Python SDK's localhost requests out of an inherited HTTP
proxy; it does not disable proxies for external downloads.

## Build and demonstrate

```powershell
./.tmp/ollama-venv/Scripts/python.exe -m eval.metrics validate --require-reviewed
./.tmp/ollama-venv/Scripts/python.exe -m ragkit.cli --config demo/ollama.toml ingest
./.tmp/ollama-venv/Scripts/python.exe -m ragkit.cli --config demo/ollama.toml ask "What are the two top-level parts that make up a Kubernetes cluster?"
./.tmp/ollama-venv/Scripts/python.exe -m ragkit.cli --config demo/ollama.toml ask "Which cloud provider offers the cheapest managed Kubernetes cluster?"
```

The index uses `data/index/t5-ollama-fixed`, separate from other index directories.
Ingest rebuilds only this configuration's collection. The inputs are the committed
frozen manifest and QA; no source, QA or review signature is edited here.

## Export for T4

Choose an unused run ID and destination. Raw answers remain local under the
ignored `raw/` directory; T4 can pass their explicit path to its `--outputs` option.

```powershell
./.tmp/ollama-venv/Scripts/python.exe -m ragkit.cli --config demo/ollama.toml batch --questions eval/qa_set.csv --run-id LOCAL-ollama-fixed-20261122 --output eval/results/raw/ollama-20261122/LOCAL-ollama-fixed-20261122.jsonl
```

Preserve the adjacent `.config.json` with the JSONL. It records effective model
settings and input hashes. Record the Ollama model digest, server version and
dependency versions alongside it when handing off. Human judges must inspect
full source text when the exported prefix quote omits a claim's evidence.

Neither successful execution nor valid citation structure establishes semantic
support, answer correctness or appropriate refusal. T4 performs independent
grading and metric aggregation. No such grades are generated by this recipe.

## Observed validation on 2026-11-22

Agent execution used Ollama 0.40.17 and model digest
`0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`.
The standalone Python 3.11.18 environment used Chroma 1.5.9, ONNX Runtime
1.32.0, NumPy 2.4.6 and OpenAI SDK 1.109.1. Frozen source hashes and T4's
reviewed-input gate passed. Ingest produced 668 chunks from 16 documents.
The cluster-components example returned a cited answer; the cheapest-provider
example refused. Full offline pytest reported 195 passed and 2 skipped; Ruff
passed. These commands were run by the agent, not personally rerun by a human.

The subsequent standard batch command completed with exit 0 and exported all
36 QA rows to the raw path above. T4 `load_outputs` accepted the artifact; the
qid set, row/sidecar run references, QA/manifest hashes and citation structure
were checked against the reopened 668-chunk index. `run.json` next to the output
records the model digest, runtime versions, code baseline and actual timestamps;
the new TOML is identified separately by its SHA-256. `handoff_check.json` records
these integrity checks only. It contains no answer grades or correctness metrics.
The raw handoff ZIP preserves the repository-relative paths so `config_ref`
continues to resolve when extracted at the repository root. Do not commit it.
